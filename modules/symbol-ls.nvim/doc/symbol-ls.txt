*symbol-ls.txt*	Go to code symbols named in markdown code spans

==============================================================================
INTRODUCTION                                                       *symbol-ls*

symbol-ls is an in-process LSP server for markdown buffers. In a code span
such as `Foo.bar` or `bar()`, it answers:

  textDocument/definition  |CTRL-]|, |CTRL-W_]|, |g]|
  textDocument/hover       |K|
  workspace/symbol         |:tag|, |:tselect|, LSP symbol pickers

It has no index of its own. It sends `workspace/symbol` for the last name
in the span to every other running LSP client and ranks the exact-name
matches. When no client has a match, it ranks the definitions that
tree-sitter `tags` queries find instead, see |symbol-ls-tags|. With no
answer from either, |CTRL-]| falls back to the tags file.

`workspace/symbol` requests to symbol-ls get only the clients' matches.

==============================================================================
TAGS QUERIES                                                  *symbol-ls-tags*

At the same time as asking the clients, symbol-ls runs `git grep` in the
project root (see |symbol-ls-ranking|) for the git-tracked files, submodules
included, that contain the name as a whole word. When no client has a
match, each file whose language has an installed parser is parsed, and the
`tags` query of that language gives its definitions: the `@definition.<kind>` matches whose `@name` is the
name (https://tree-sitter.github.io/tree-sitter/4-code-navigation.html).
Hover for such a match shows its file, its `@doc` text, and the comment
lines directly above the definition with the definition's first line.

The `tags` query of a language is downloaded from its grammar repository at
the revision that nvim-treesitter's parser registry names, on the first
lookup in that language and again when the revision changes. Queries go to
`stdpath("data")/symbol-ls/queries/<lang>/tags.scm`, a directory that
|symbol-ls.setup()| adds to 'runtimepath'. Revisions, and repositories with
no `tags` query, are recorded in `stdpath("data")/symbol-ls/revisions.json`.

==============================================================================
SETUP                                                      *symbol-ls.setup()*

>lua
    require("symbol-ls").setup({ filetypes = { "markdown", "quarto" } })
<
Attaches to every buffer of {filetypes}, open now or later, and maps Visual
`K` and `CTRL-]` in it (|symbol-ls-visual|). Markdown buffers with a
'buftype' (hover floats, plugin scratch buffers) are skipped. Other
filetypes are attached whatever their 'buftype'.

{filetypes} defaults to `{ "markdown" }`.

|CTRL-]| goes through the 'tagfunc' that core sets, see |lsp-defaults|. A
buffer with its own 'tagfunc' gets |CTRL-]| from symbol-ls only if that
function falls back to |vim.lsp.tagfunc()|.

==============================================================================
TERMS                                                        *symbol-ls-terms*

A code span names a symbol path. The separators `.`, `:`, `::` and `#`
split it into qualifiers and the symbol, and a trailing argument list is
dropped:

  `Foo.bar`        symbol bar, qualifier Foo
  `a::b::c`        symbol c, qualifiers a and b
  `foo.bar(x, y)`  symbol bar, qualifier foo

Text that is not an identifier path, such as `rg -n`, gets no answer.

                                                          *symbol-ls-visual*
In Visual mode the selected text is the term, in or out of a code span.
Surrounding backticks in it are dropped. A selection over several lines
counts as none, and the code span at the cursor is used. Visual `K` and
`CTRL-]` are mapped buffer-local in attached buffers: they call
|vim.lsp.buf.hover()| and |vim.lsp.buf.definition()|, then leave Visual
mode. Several definitions go to the quickfix list, not a tag list.

==============================================================================
RANKING                                                    *symbol-ls-ranking*

Only matches named exactly as the symbol are kept. They are sorted by, best
first:

1. A qualifier equals the match's `containerName` or its file name without
   extension, ignoring case, `_` and `-`. The last qualifier counts most.
   When some match has such a qualifier, the others are dropped.
2. The file is under the project root. For a file buffer that is its `.git`
   root (none outside a repository); for other buffers, the current
   directory of a window showing the buffer, else of the current window.
3. The file is not a test file (`*.test.*`, `*_spec.*`, `*_test.*`,
   `test_*`, or under `tests/` or `spec/`).

Hover shows the best match only; definition returns all matches.

==============================================================================
LIMITS                                                      *symbol-ls-limits*

- symbol-ls waits at most 800 ms for the other clients and ranks the replies
  that arrived. Each client that times out or fails is reported with
  |vim.notify()| at WARN.
- |CTRL-]| falls back to the tags file when any client attached to the
  buffer takes over 1 s to answer, e.g. a client that is still starting.
- Matches whose location has no range (a `WorkspaceSymbol` that needs
  `workspaceSymbol/resolve`) are dropped.
- |symbol-ls-tags| needs a project root inside a git repository, git, curl,
  and nvim-treesitter. Languages without a parser, a registry entry on
  GitHub, or an upstream `tags.scm` get no answer from it.
- |symbol-ls-tags| skips files over 1 MB and stops reading at 5 MB in total.
  Files whose name without extension matches a qualifier are read first.
- A `tags` query that raises an error, such as one that fails to parse with
  the installed parser or uses a predicate Neovim lacks, is reported once
  with |vim.notify()| at WARN, and its language gets no answer until
  restart. A parse error happens when the parser is not the one
  nvim-treesitter installed, e.g. one bundled with Neovim at another
  revision.
- Matches from |symbol-ls-tags| have no `containerName`.
