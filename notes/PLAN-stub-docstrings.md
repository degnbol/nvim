## Background

Hover on a numpy symbol gives a type and no documentation, in two shapes:

```python
total = counts.sum(axis=0, keepdims=True)   # (method) def sum(...) -> Any
np.divide                                   # (variable) divide: _UFunc_Nin2_Nout1[...]
```

Hover on `np.sum` gives the full docstring. The difference is not the symbol but
where its implementation lives. All three are declared in `numpy/__init__.pyi`,
which carries no docstrings; basedpyright's fallback is to read the docstring off
the *source* the stub shadows:

- `np.sum` → `numpy/_core/fromnumeric.py`, a Python function. Found.
- `counts.sum` → `numpy.ndarray.sum`, a C `method_descriptor`.
- `np.divide` → a `numpy.ufunc` instance, declared as an annotated assignment.
  106 of numpy's module-level names are ufuncs.

For the last two `inspect.getsourcefile` raises, so there is nothing to fall back
to. basedpyright already solves this for the standard library by shipping a
*docified* typeshed, with the docstrings written into the `.pyi` text. Third-party
inline stubs get no such treatment. The general case is a compiled implementation
behind a `.pyi`; the fix is the one basedpyright uses.

### Where the fixed stubs go

Vendored under `stubPath`, generated by `RUNME.sh`, exactly as rdkit's are —
"so this copy wins over any `rdkit-stubs` installed in a project's env". One
artefact covers every project, with no per-project step and nothing to re-apply.
It version-locks numpy's types to whichever numpy `RUNME.sh` reflected, which is
acceptable against a policy of tracking current numpy. Size fits the precedent:
~3.2 MB against rdkit's 2.9 MB and pyrosetta's 18 MB.

`stubPath` does not reach a project owning a `pyrightconfig.json` or
`[tool.basedpyright]` — basedpyright discards the language server's `stubPath`
there. `stub_fixes.lua` already exists for that case and covers it by rewriting
the environment's own stubs in place. It should also be self-limiting: it locates
an environment from the `textDocument/definition` answer, and where `stubPath`
wins that answer points into `lsp_ext/python_stubs/numpy/` rather than a
`site-packages`, so `env_of` returns nil and nothing fires. Confirm that during
implementation rather than assuming it.

### The rule

For every declaration in the stub whose runtime counterpart has a docstring and
no Python source, write that docstring into the stub. Two node shapes:

- a `...`-bodied `def` — docstring before the `...`, as typeshed does;
- an annotated assignment (`divide: _UFunc_Nin2_Nout1[...]`) — a string literal
  on the following line. Verified: basedpyright renders it, so `np.divide` hovers
  with its 2057-character ufunc documentation.

"No Python source" is what keeps the file small and keeps basedpyright's own
fallback in front: where `getsourcefile` succeeds, inserting only duplicates what
hover already finds.

**Every declaration of a name, not the first.** Measured: with the docstring on
the first overload only, hovering a call that binds to a later overload returns
the signature and nothing else. basedpyright does not fall back to a sibling
overload, which is why typeshed repeats the text on both `str.upper` overloads.

### Why not `docify`

`docify` produces basedpyright's typeshed and was the obvious candidate. Measured
against numpy 2.5.3:

1. **It writes nothing into `numpy/__init__.pyi`** — 0 docstrings before and
   after — and aborts with a bare `TypeError`. Both `libcst` and the stdlib `ast`
   parse that file, so this is a docify defect, not a syntax limit. That file
   holds `ndarray`, `generic` and all 106 ufuncs.
2. It depends on `libcst`, a native extension, so it cannot be injected by
   `PYTHONPATH` into an arbitrary target interpreter the way prior art is.

An earlier draft blamed the miss on `sum` living in the stub-only class
`_ArrayOrScalarCommon`. That is wrong: `ndarray` overrides `sum` with 16
declarations of its own against that class's 3, and the live hover binds to an
`ndarray` one. Plain reflection reaches it. The alias is still needed, for the 35
names reachable only through `_ArrayOrScalarCommon` (`T`, `clip`, `round`,
`conj`, `tobytes`, `flags`, `dump`, `argsort`, …).

`_ArrayOrScalarCommon` is also the base of `generic`, so the single alias puts the
array text on scalar members. That is wanted: the runtime's own
`'Scalar method identical to \`ndarray.sum\`.'` is another pointer, and the array
text is the useful one.

### Measured cost

numpy 2.5.3, applying the rule (1648 declarations in `__init__.pyi` alone):

| | `numpy/__init__.pyi` | whole tree |
| --- | --- | --- |
| pristine | 278 kB | 1922 kB (275 files, 111 of them unimportable test fixtures) |
| + this pass | ~515 kB | ~3252 kB (2323 declarations) |

Hover latency against a tree this pass produced is **not yet measured** — an
earlier figure was taken against a tree whose `__init__.pyi` was untouched, so it
measured nothing. Measure it as a validation step.

## Changes

### New `lsp_ext/python_stubs/fix_stub_docstrings.py`

Stdlib only, `<env python> fix_stub_docstrings.py <package> [--out DIR | --in-place]`,
matching prior art so `RUNME.sh` and `stub_fixes.lua` drive it the same way. Head
marker `# fix_stub_docstrings: <package> <version> <sha>`.

```python
CLASS_ALIASES: dict[tuple[str, str], str] = {
    # Keyed on (module, class) as prior art's _CLASS_OVERRIDES is: a bare class
    # name would also alias a same-named class in a submodule.
    ("numpy", "_ArrayOrScalarCommon"): "ndarray",
}

def runtime_docstring(obj) -> str | None:
    """Docstring of an object with no Python source, else None.

    The condition is `inspect.getsourcefile` raising: where it succeeds,
    basedpyright reads the docstring from there already.
    """

def document_stub(text: str, module) -> str:
    """Every ...-bodied def and annotated assignment gets its runtime docstring.

    Every declaration of a name, not the first: overloads do not inherit.
    Emitted as r\"\"\"...\"\"\" so the 230 numpy docstrings containing backslashes
    survive; a docstring containing \"\"\" (3 in numpy) is skipped.
    Idempotent: a declaration already carrying a docstring is left alone.
    """

def stub_root(package: str) -> pathlib.Path:
    """`<package>-stubs` where it exists, the package's own directory otherwise
    — the precedence pyright applies."""

def patch_dir(root: pathlib.Path, package: str) -> None:
    """Rewrite in place. Not prior art's `patch_staged`, which renames the tree
    aside: for inline stubs that would rename the live `numpy/` package with its
    loaded .so files."""
```

Behaviour carried over from prior art, each for a reason measured in numpy:

- `redirect_stdout(devnull)` around introspection — attribute access while
  walking numpy prints f2py's ~150-line usage banner, and `stub_fixes.lua:104`
  appends stdout to its notification.
- `side_effect_free`, **parameterised** as `side_effect_free(parts, patterns)`
  with each fixer owning its tuple: 111 of numpy's 275 `.pyi` files are
  type-check fixtures under `numpy/typing/tests/data/` with no importable module,
  and prior art's pattern list is rdkit-tuned.
- explicit `encoding="utf-8"` — 42 numpy docstrings are non-ASCII.
- strip a previous marker line before prepending the new one.
- write only files that changed, so skipped fixtures and all-Python modules stay
  pristine.
- report modules that could not be imported.

### `fix_pybind_stubs.py` and its test

Two helpers are unusable by a second caller and must be parameterised:
`script_fingerprint()` hashes its own `__file__`, and `marker_line()` hardcodes
`"# fix_pybind_stubs:"`. Left as they are, a marker built from them could never
match `stub_fixes.patched_by_current`, which hashes `fix.script` — so every
environment would be re-offered forever. → `script_fingerprint(script)`,
`marker_line(prefix, package, script)`. `test_fix_pybind_stubs.py` asserts the
current no-arg forms and changes with them. Lift these plus `module_name`,
`introspection_order`, `side_effect_free`, `package_version` and `stub_root` into
a `stub_tools.py` sibling both fixers import.

### `lsp_ext/python_stubs/RUNME.sh`

A numpy entry beside the rdkit one, vendoring a documented copy:

```zsh
# numpy's ndarray methods and its 106 ufuncs are C objects behind a .pyi, so
# basedpyright has no source to read their docstrings from.
uv run --no-project --with numpy python3 fix_stub_docstrings.py numpy --out numpy
```

### `lua/autocmds/stub_fixes.lua`

- **No prompt.** `consider` patches instead of asking, and `M.patch`'s existing
  success notification reports what was done. Applies to both fixers. Drop the
  `prompting`/`declined` states with it.
- Derive the stub directory rather than adding a field — the same precedence
  pyright uses, self-correcting if a package later ships a sibling:

  ```lua
  local pkg_dir = root .. site .. "/" .. pkg
  local stubs = vim.uv.fs_stat(pkg_dir .. "-stubs") and pkg_dir .. "-stubs" or pkg_dir
  ```

  rdkit is unaffected: with no sibling, its probe `Chem/rdmolfiles.pyi` does not
  exist under `rdkit/` either, so the check still skips. Update the `@field` docs
  on `StubFix.pkg` and `StubFix.Env.stubs`, the module header, and
  `tests/plenary/stub_fixes_spec.lua`.
- New `M.fixes` entry for numpy: `probe = "__init__.pyi"`,
  `marker = "# fix_stub_docstrings:"`, pointing at the new script.

### Tests

`test_fix_stub_docstrings.py` against a fixture tree: a C-implemented member gets
its docstring, a Python-implemented one does not, every overload gets it, an
annotated assignment gets one, an aliased stub-only class resolves, a docstring
with backslashes survives, a second run changes nothing.
`stub_fixes_spec.lua` gains the inline stub-directory case and loses the prompt.

## Expected outcome

`K` on `counts.sum` at `smooth.py:106` shows the matched signature followed by the
method's documentation, ending at `Refer to \`numpy.sum\` for full documentation.`
`K` on `np.divide` shows the ufunc documentation instead of
`_UFunc_Nin2_Nout1[...]` alone. No extra overloads: both are non-overloaded at
those sites. The same text reaches blink.cmp's completion documentation, which
reads the same stubs.

Both shapes verified end to end by splicing the docstring into the stub by hand
and re-issuing the hover.

## Non-goals

- **Resolving `Refer to X for full documentation.` inside the stub.** 253
  occurrences, every target resolvable by attribute walk — excluded on size: it
  would take `__init__.pyi` to ~1386 kB, 5× pristine, because the text multiplies
  by overload count. `notes/PLAN-k-doc-lookup.md` reaches the same text on demand
  at no stub cost.
- **Revising an already-patched tree.** The pass only fills empty declarations, so
  a later version of the script cannot improve its own output — only regeneration
  or a package reinstall can. State it in the module docstring.
- **Packages other than numpy.** The pass is package-agnostic; only
  `CLASS_ALIASES` is not, and it is empty for anything that does not need it.
